## 已核实的数据边界

| 位置 | 实际行为 | 本轮前端处理 / 后续后端任务 |
| --- | --- | --- |
| `archiveController.loadStudentArchive` | 课程仅筛 active 报名，DTO 有 enrollment_id、无 course_id；没有同时限定 published | 用课程列表与反思报名映射交集核验。后端应补齐当前课程有效性及 course_id，另行明确历史档案保留政策 |
| 同函数作品、反思、评价 | 学生本人记录可含撤回课程、失效报名；作品 DTO 有 course_id/enrollment_id，其余靠 enrollment_id | 统一按 ID 过滤，所有统计取可展示集合；不能按同名课程标题推断归属 |
| 同函数 ability | SQL 按返回作品集合中的 work_reviews 求五维均值 | 仅在原作品集合全部可见时展示，否则暂不可汇总；后端应返回范围明确的聚合及覆盖信息 |
| 同函数 growthRecords | 有 work_id 的提交/评审事件可关联；部分累计系统记录、遗留兜底文本无对象 ID | 不解析标题或猜时间，隐藏无关联系统详情；后端应补全对象 ID 和事件语义。明确 event_type=teacher 且有 recorded_by 的记录按个人观察保留 |
| `archiveController.showReflection` | 返回有效报名，未完整筛课程发布状态 | 首次进入就与 courseAPI.list 取交集，选项失败不伪装空数据 |
| `archiveController.submitReflection` | 检查已有 enrollment 的本人和 active 状态，但未核对课程发布；enrollment_id 与 difficulty 在服务端也未强制必填 | 本轮保留原前端必填并在提交前重验课程。后端仍应独立核验发布、必填与关联；重验与提交间的竞态不能由前端消除 |
| 同函数日限额 | 按 `date(created_at, '+8 hours')` 统计本人当天所有反思，含 report_id 反思；独立日志限 1 篇，报告提交流程没有同样限额 | 真实 API 验证限额拒绝；保留四个输入，不改配额、不阻止原报告提交。是否调整应由产品与后端决定 |
| `learningService.lessonPackage` / `learningGate.latestReport` | 选定课时才能获得最新报告；没有档案报告索引、完整报告版本目录或评审人姓名（仅 reviewer_id） | 按需读取，显示真实状态、版本、评语、评分与评审时间，导师姓名缺失明示；如需姓名与全量索引应提供准确 DTO，不额外读取用户管理接口 |
| 报名 `completed_at` | 当前没有可依赖的常规自动写入逻辑 | 不凭报名、报告通过、作品通过推算课程完成；只展示实际已存在日期 |

## 实际验证与限制

隔离临时 SQLite 中，未发布课程的作品/反思/评价仍由原档案接口返回；页面交集过滤后未展示，能力汇总降级。课程撤回、报名移除与读取中途撤回均验证了记录和统计清理。独立反思成功 POST 后可在 GET 档案读取，日限额由真实接口拒绝，前端没有保存假成功。

上述修正是展示边界，**不代表直接请求档案、作品、下载或反思接口的服务端课程授权已修复**。仍需结合 `deliverables/作品课程有效性-后端待办.md`（工作区原记录）另行处理。账号失效、强制改密继续交给原全局认证流程。

没有新增正式积分、兑换、徽章、证书、签到、热力图、学习时长或角色能力算法。作品评分仍为问题发现、方案设计、动手操作、数据分析、表达展示；报告评分、课程评价、作品评分不能合成总分。
