# 旧数据、草稿与提交规则

迁移 020 只给 reflections 增加 reflection_version（默认 1）和 entry_note/together_note/extra_note。原 difficulty/solution/improvement/new_question 保留，历史记录不转换正文、不截掉第四项。新库 schema 同步包含字段，旧库安全迁移重复启动只记一次。

新记录显式提交版本 2，三框任一有非空白内容即可；空记录、非文本、超过 2000 字、混合版本拒绝。旧版本 payload 仍接受原字段，按旧标签阅读。正文保留原文/标点；“去末尾句号”仅在显示组件处理，不写回教师原文。

学习报告仍需要原 summary 和课堂回顾/卡片门槛。报告提交、退回、再提交第 2 版、评分通过都走原记录关系；不修改作品版本或课时完成比例。独立日志的“每天一篇”查询仍统计该学生当天 reflections，**包括报告附带反思**，日期边界按北京时间。报告附带反思没有新增独立日志限次检查；当天已有报告反思时，另交独立日志可能被原限次挡住。

独立日志旧端点此前允许缺少报名；本轮与课程空间要求统一，写入前检查本人有效报名、课程已发布、课时属于该课程且未取消，未开放跨课生活日志共享。负责导师、分配教师及管理员只读范围沿原档案规则；新媒体、同学、无关导师/教师不能读，不把正文发送到助手。

## 草稿

- 报告保留原本浏览器 key `star-voyage:report:v1:<账号>:<课程>:<课时>`。检测到旧四项草稿时先留 `<key>:legacy-v1` 独立原样备份，四项带原标签映入新框，不把“困难”直接伪称成“心情”。备份失败则阻止覆盖旧草稿，提示自行保留文字。
- 独立日志在本浏览器 `pbl:reflection-draft:<账号>:<报名>` 保存，课程报名与账号隔离；遇到旧结构时也保存 `:legacy-v1`。未提交草稿不上传，不保证换设备恢复。服务器提交成功再清除当前草稿，备份仍保留。
- 网络失败、日限失败保留当前输入。账号/课程组件 key 与读请求序列隔离迟到响应；授权撤回后的教学内容不可继续显示，草稿不作为放行依据。
- 维护表单草稿保持在当前页面，未保存离开/刷新有确认；不是服务端自动保存。新增写成功读失败会保留真实 ID 和表单值，当前保存状态明确；重新读取失败不丢弃输入。上传队列仍保留原 uncertain/失败/成功状态、真实对象 ID 与 upload_token；成功/取消的历史不占 20 个待处理名额，不把未确认传输伪称成功。

本次真实教学库在迁移前已停止新服务并一致备份至 `.local/teaching-before-step02-20261008`。只读核对 45 张表原字段一致、已有上传和反馈文件字节一致、integrity_check=ok、外键违规 0；见 data-protection.json。认证 refresh_tokens 不作业务数据对比。合成教材、上传、故障、评审写入全部在另建隔离库进行。
