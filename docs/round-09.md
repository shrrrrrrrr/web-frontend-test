## 本轮核实与修复

1. 原 AuthContext、Login 和 Axios 直接访问 storage，getter/读写抛错可中断恢复或渲染。现在统一延迟获取、捕获 getter/getItem/setItem/removeItem，恢复始终结束 loading，只信任 me 校验返回的用户。无法保存凭据不会进入业务，也不改成内存登录。保存前设置 pending 标记，部分失败清理身份键；无法清理时留下标记拒绝恢复混合凭据。
2. 退出和失效同步停止当前页面并触发账号卸载，即使存储清理失败也不会继续显示旧内容。内存序号阻止旧账号请求、迟到刷新写回；跨标签身份变更重新核验。session notice 仅是提示，获取/写入失败不影响认证入口。成功登录后才恢复请求资格。
3. 401 仍只刷新并重试一次，沿用原 5 分钟提前刷新、15 秒请求超时和同页并发去重。迟到 401 先检查是否已被并发刷新替换，避免再轮换。普通网络/业务 403/404 不登出；FORCE_RESET 更新强制标记并交给布局拦截，避免跳转循环。课程对象错误继续原定向重验。
4. 原通知/反馈 A 切 B 时旧详情未清，B 失败后可出现旧内容和新 ID 按钮。现在按账号、对象和筛选建立读取生命周期：新对象即加载，旧请求和动作完成回调不再更新新对象。404/403、临时失败与空态分开。
5. 写成功后回读失败不再归为写失败。回复确认后清空已发送输入；批量操作/回复提示“已完成操作，显示暂未刷新”，重新读取只 GET。普通写失败保留文字。附件 404 仅影响附件，不清有效反馈或回复。
6. 真实浏览器检查中修复了通知弹层空内容导致不能首次打开、关闭后缓存旧内容、窄屏左侧裁切及关闭按钮对比度问题。加载后的弹窗确认按钮使用稳定可访问名称。管理员公开回复和内部备注使用不同表单 ID，标签不会聚焦到另一表单。
7. 正常退出和明确失效只提供重新登录说明；只有可恢复的会话读取错误才显示重新读取按钮，避免给已停止会话提供无效重试。

## 环境与后端边界

- 退出接口仅撤销对应 refresh token，不撤销已签发 access token；前端不声称即时服务端全会话撤销。若无法读取 refresh 或网络无法送达，当前页仍停止，但不能保证服务器收到退出请求。
- 如果浏览器同时拒绝所有存储读写/清理、无法保存任何停止标记，且服务器又不可达，前端无法保证关闭并重开浏览器后旧凭据已被销毁。当前页有立即停止保护；可写标记存在时拒绝恢复并要求重新登录。存储恢复后需显式登录，不能把未清理记录当作已退出成功证明。
- 反馈写接口没有幂等键。按钮在当前请求内防重复；超时/断网未确认结果时说明不确定，应先读取记录，不能承诺跨请求恰好一次提交。
- 通知详情 GET 自动已读是原接口行为；本轮不增加只读预取接口。后端列表和计数对 withdrawn 状态的过滤口径存在原有差异，沿用现状，不擅自更改后端。
- 故障测试通过隔离浏览器替换 Storage getter/方法、拦截单个请求、延迟响应执行，不能等同所有浏览器隐私模式均已验证。
- 正式课程内容和章节归属仍待提供；本轮截图均明确为测试数据。奖励规则不变，小智完整页、旧任务列表、旧课程学习/回放兼容页面仍留待后续。

## 尚未解决的奖励深度回归

完整第八轮回归重复运行时，双标签 Web Locks 的“先兑换、后重置”用例不稳定：页面可能仍显示 80，而预期是重置后的 120。曾有一次带诊断的全套 8 场景通过，但后续复跑仍失败，因此**不将完整奖励回归报告为通过**。

为区分本轮认证改动与既有存储行为，在两个全新的 Edge 空白页中执行最小复现：不加载应用、React、认证或后端；先让另一标签缓存空值，再用同名 Web Lock 排队 setItem('80') 与 removeItem。25 次中有 1 次两页最终仍读到 '80'。独立复现表明当前 Edge 在锁队列结束后仍可能保留错误存储值，推断与跨标签缓存或消息时序有关，浏览器内部原因尚未确认；不能承诺既有奖励重置的跨标签原子性。

- 复现命令：node scripts/diagnose-edge-storage-locks.mjs。它只打印本次观测，属于概率性诊断；单次未复现不能证明问题不存在。页面通过 Playwright route 提供，不访问真实用户服务。
- 本轮未修改奖励适配器、存储格式或规则。该问题登记为后续奖励存储专项；不得扩展为本轮已保证可靠的能力。
- 相关基础回归采用明确命令 node --test --test-skip-pattern='实际 Web Locks' tests/round8.browser.test.js；仅跳过上述已登记的深度队列场景，不跳过本轮认证、账号隔离、普通演示兑换、失败恢复和界面验证。
- 原回归另有登录按钮宽泛匹配、路由尚未卸载就断言样式、窄屏布局未稳定就读取滚动位置的问题。测试改为明确目标、等待路由/布局及真实存储事件，保留原业务断言，没有修改实现来配合测试。

基础回归最终结果：命令退出码 0，7 个业务场景通过（含父测试 Node 计数 8 / 8）。该结果不包含被命令明确排除的深度队列用例；不能当作完整第八轮回归通过。与本轮 22 个场景、学习/权限 17 个场景合计，46 个业务场景通过，另保留上述 1 个未通过的深度场景。
