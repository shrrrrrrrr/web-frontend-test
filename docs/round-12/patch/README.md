## 原因与真实复现

在未修复的 StudentScope 上，使用真实本机后端、临时 SQLite 和 Edge：进入可用课时 → 测试库取消课时 → 真实接口失败触发失效挡板 → 点击“返回探索地图” → 后端恢复课时 → 点击“进入课程地图”→ 第 1 关节点 → “进入课时”。全程沿用同一文档和登录会话。

同账号的 `GET /api/learning/lessons/1` 返回 **200**，正确课时 URL 仍被旧挡板拦住，而且没有重新检查按钮。[修复前复现日志](evidence/reproduction-before-fix.txt) 在缺少按钮的断言处失败：6 个业务场景通过，1 个恢复场景及其父测试失败。之前的 `page.goto` 会重建容器，不能证明这条站内路径正常。

## 最小修正

- 失效挡板恢复现有“重新检查”，复用原 `check(true)`，保留“返回探索地图”。真实核验成功后，原逻辑仅解除匹配对象的旧阻断。
- 核验等待期间不显示旧正文；403/404、课程撤回、报名移除均继续阻断。临时网络失败时在挡板内显示原核验提示，按钮仍可再次尝试。
- 应用源码仅修改 `frontend/src/student/StudentScope.jsx` 的挡板展示。没有改动请求逻辑、监听、挂载 key、账号切换、令牌刷新、草稿存储或后端授权。
- 权限回归改为真实站内点击，并检查原 `document` 始终保留。第十二轮撤课回归删除“不能出现重新检查”的非业务限制，改成主动检查仍不得显示地图节点。
